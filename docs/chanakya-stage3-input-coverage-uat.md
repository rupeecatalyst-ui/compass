# CHANAKYA Stage 3 input-coverage UAT

Reviewed base: `53a2c20ada2384b969ca22b90814a44d92511153`, branch `feat/canonical-lender-recommendation-stage1`.

**UAT acceptance: FAIL / remediation required.** This report characterizes the frozen implementation; it does not certify production data. No application, Stage 1, Stage 2, schema or migration file was changed. No database was accessed. Production-data certification remains **PENDING — RELEASE GATE**.

## Main findings

1. The Opportunity Financial Details editor writes salary using `absoluteRupeesToStoredString(..., { overridePrefix: true })`, for example synthetic `override:100000`. The Stage 2 hook applies `Number()` after comma removal only. That valid UI value becomes null. Plain numeric stored values work, so the earlier Stage 2 fixtures did not detect this UI-format mismatch.
2. Financial/property stated drafts persist in browser localStorage, not authoritative saved Opportunity financial columns. `persistDraft()` separately saves loan participants to `lendingExtension.participants`; it does not save the stated financial/property draft there. The endpoint consumes five browser-declared fields, plus saved Opportunity product, amount, employment, city and CIBIL. It does not consume the Contact, participant financial profiles or COMPASS answer snapshot.
3. Residency, applicant type, DOB, requested tenure and BT technical facts do not reach the assessment. Saved `lendingExtension.btAmount` is not mapped to outstanding. Optional COMPASS data can exist on the same Opportunity, but this mapper ignores it.
4. **Input capture alone cannot repair the path.** Stage 1 builds `canonicalConstraints` and `parsedPolicyRules`, but no engine/service consumer applies these objects to the borrower. Synthetic tests return recommendations despite missing constrained residency and below-threshold programme/policy CIBIL. Policy-link validation and rejection of unsupported rule *types* still operate; a recognized `cibil_range` is parsed but not enforced.
5. Stage 1 also passes through `policyAssessmentJson` without projecting its engine fields. For example, stored seasoning, repayment-clean and self-employed methodology settings do not become `requiredSeasoningMonths`, `repaymentCleanRequired` or `selfEmployedMethodologyPresent`. A schema-compatible fixture demonstrates this. No extra top-level database columns were invented for the fixture.
6. Missing DOB does not make age-constrained tenure fail closed: the engine can use programme maximum tenure without the age cap. Missing BT outstanding can yield a transfer component equal to the tentative offer. These are observed frozen-engine behaviors, not approved defaults.
7. Self-employed capture has turnover, constitution and vintage, but the customer contract has no turnover/methodology inputs, and the engine has no self-employed income-capacity calculation. Adding a boolean methodology flag is not an adequate remedy.

## Category summary

- **Complete server-backed inputs:** organization, product, requested amount, saved employment-family mapping, transaction-derived journey, expected CIBIL representation, city transport. This is transport completeness, not proof that every associated programme constraint is enforced.
- **Correct local-only transport:** numeric obligations, positive property value, property type and constitution. Native salary override format is broken. Local-only values are not server-persisted Opportunity assessment truth.
- **Captured but not mapped:** BT outstanding, state, applicant kind/participants, stated turnover/vintage/location; salary captured but incorrectly parsed. Programme JSON assessment settings also lack mapping.
- **Available elsewhere but not mapped:** Contact DOB/resident status/occupation; optional COMPASS DOB/residency/co-applicant/BT/property technical answers. Do not automatically trust legacy resident-status defaults.
- **Not currently captured on this native path:** requested assessment tenure; dedicated co-applicant income/EMI/age assessment; BT start-date/EMI/ROI/certainty/repayment/technical property controls; explicit property geography. Some exist elsewhere as category C rather than being globally absent.
- **Optional:** asOf (execution clock), customer-selected tenure when no customer preference is required, provenance flag; original sanction/tenure and rate type are currently unused context. Programme-conditioned fields must not be described as universally optional.
- **Unsupported:** turnover-based/self-employed capacity, DBR, dedicated applicant-type/profession/geography/documents enforcement; top-up in approved canonical products; recognized CIBIL rules and several canonical constraints are parsed/copied but not consumed.
